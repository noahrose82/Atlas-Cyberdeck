# Atlas Cyberdeck — Audience Outreach Plan

## Principle

> **Earn attention with proof. Do not spam communities with a Kickstarter link.**

The strongest Atlas content is the running product.

---

# Content Pillars

## 1 — Real Ubuntu on Android

Content:

- physical phone;
- Ubuntu version;
- ARM64;
- Python;
- package tools.

Hook:

> "This is Ubuntu 24.04.4 running on my Android phone. Android isn't rooted."

## 2 — Atlas vs. Ubuntu

Content:

- Atlas Shell;
- `linux shell`;
- transition to Ubuntu.

Hook:

> "Atlas isn't just a Linux terminal. The app has its own shell and controls a separate Ubuntu runtime."

## 3 — Safe Failure

Content:

- `safety trip-test`;
- Safe Mode;
- Recovery Mode;
- repair.

Hook:

> "What happens when a mobile Linux environment breaks package state? Atlas fails closed."

## 4 — Engineering Build Log

Content:

- architecture decisions;
- PRoot integration;
- RootFS;
- runtime metrics;
- tests.

Hook:

> "Building a Linux runtime on Android is mostly edge cases. Here's one we had to solve."

## 5 — Why Build It

Content:

- founder story;
- pocket workstation philosophy;
- technical independence.

Hook:

> "I wanted my phone to be more than a consumption device."

# Channel Strategy

## GitHub

Purpose:

Technical trust.

Content:

- polished README;
- architecture;
- roadmap;
- screenshots;
- build progress;
- issue discussions when public contribution is appropriate.

CTA:

`Follow the Kickstarter pre-launch page`

## Reddit

Purpose:

Technical feedback and community discovery.

Approach:

- participate in relevant communities;
- lead with technical value;
- share real details;
- follow each community's self-promotion rules;
- avoid copy-pasting the same promotional post everywhere.

Potential community themes:

- Android development;
- Linux;
- Termux/mobile Linux;
- homelab;
- cyberdecks;
- programming;
- cybersecurity students.

Research each community's current rules before posting.

## LinkedIn

Purpose:

Professional credibility and founder/build story.

Content:

- engineering milestones;
- real-device demo;
- Android/Linux architecture;
- lessons learned;
- project-development narrative.

## YouTube / Shorts

Purpose:

Product proof.

Formats:

- 30-second real Ubuntu demo;
- Safe Mode / recovery demo;
- 3–5 minute technical walkthrough;
- development logs.

## TikTok / Reels

Purpose:

Discovery.

Use real device interactions.

Avoid generic "hacker aesthetic" content.

## Discord / Technical Communities

Purpose:

Conversation and high-quality feedback.

Approach:

Contribute first. Share Atlas when relevant and permitted.

# Four-Week Minimum Warm-Up

This is a suggested Atlas operating plan, not a Kickstarter requirement.

## Week 1 — Proof

Publish:

- hero;
- real Ubuntu demo;
- landing page;
- email signup.

Measure:

- comprehension;
- signups;
- audience source.

## Week 2 — Architecture

Publish:

- Atlas Shell vs. Ubuntu;
- Linux Manager;
- package/storage metrics.

Ask:

- what would users actually use it for?

## Week 3 — Safety

Publish:

- Safe Mode;
- controlled recovery;
- why package integrity matters.

Ask:

- top technical concerns.

## Week 4 — Campaign Intent

Publish:

- 1.0 scope;
- Kickstarter funding story;
- pre-launch page;
- notify-on-launch CTA.

Measure:

- Kickstarter follows;
- likely day-one backers;
- reward response.

Continue longer than four weeks if the audience gates are not reached.

---

# Outreach Rule

Do not launch because the calendar says "Week 4."

Launch when the audience evidence supports it.
